# 智能代理算法说明文档

## 1. 方案概述

本方案面向移动端应用的通用 GUI 自动操作任务，目标是在未知应用、未知页面结构和多样化自然语言指令下，稳定输出下一步可执行动作。系统采用“多模态大模型决策 + 坐标网格视觉增强 + 历史阶段提示 + 条件式自修复 + 通用后处理”的混合式智能代理架构。

与单纯依赖大模型直接输出动作不同，本方案将任务拆成可控的决策链路：先把当前截图、归一化坐标网格、用户指令和动作历史组织成结构化上下文，由视觉语言模型给出初始动作；再通过鲁棒解析、自修复判断和通用 UI 行为规则进行校验与纠偏；最终输出符合评测协议的 `CLICK`、`TYPE`、`SCROLL`、`OPEN` 或 `COMPLETE` 动作。

算法不针对某一个具体 APP 编写固定流程，也不记忆测试样例答案，而是抽象出搜索、填写评价、内容互动、路线查询、价格查看、播放收藏等移动应用中的通用任务形态，以增强跨应用泛化能力。

## 2. 总体架构

整体流程如下：

```text
AgentInput
  -> 截图预处理与坐标网格增强
  -> 构造系统提示词和用户提示词
  -> 调用多模态大模型生成初始动作
  -> 解析并规范化动作 JSON
  -> 判断是否存在高风险决策
  -> 必要时发起二次修复决策
  -> 通用后处理规则校正
  -> AgentOutput
```

核心模块包括：

| 模块 | 作用 |
| --- | --- |
| 输入构造模块 | 将原始截图、坐标网格图、指令、步数和历史动作压缩为模型可理解的上下文 |
| 多模态决策模块 | 基于截图和任务语义选择下一步操作 |
| 动作解析模块 | 从模型输出中提取并规范化合法动作 |
| 条件自修复模块 | 对高风险动作追加一次纠错提示，降低误点、误完成和误滚动概率 |
| 通用后处理模块 | 用任务阶段和移动端 UI 通用先验修正动作 |
| 稳定性控制模块 | 处理 UTF-8、API 重试、非重试错误识别和点击边界安全 |

## 3. 输入与视觉增强设计

移动端 GUI 任务的难点之一是模型需要同时理解页面内容和精确点击位置。本方案在每一步向模型提供两张图：

1. 原始截图：保留真实 UI 外观、图标、文字和布局。
2. 坐标网格截图：在同一截图上叠加归一化坐标网格，帮助模型把视觉目标映射到 `[0, 1000]` 范围内的点击坐标。

这种“双视图”输入可以降低模型在复杂页面中的坐标漂移问题。模型仍然依据真实截图判断目标控件，但在给出坐标时可以参考网格图定位，从而提高点击动作的可执行性。

用户提示词中还会加入：

- 用户原始指令。
- 当前步数。
- 截图尺寸。
- 最近若干步有效/无效动作摘要。
- 当前任务专项提醒。
- 当前阶段提醒。

历史动作不会无限增长，而是保留最近窗口，兼顾上下文有效性和 token 成本。

## 4. 任务理解与阶段提示

系统通过正则和轻量语义规则从自然语言指令中抽取任务类型和关键信息，例如：

- 搜索、查找、播放、收藏、评论区等搜索型任务。
- 评价、好评、晒单、反馈、追评等表单填写任务。
- 点赞、喜欢、关注、进入作者主页等内容互动任务。
- 打车、导航、航班、酒店等路线或筛选任务。
- 购买、下单、支付、加购、规格选择等交易任务。
- 查看价格、多少钱、最便宜等信息查询任务。

在此基础上，代理生成两类提示：

1. 任务专项提醒：说明该任务通常应优先寻找搜索框、评价入口、底部操作栏、内容卡片或显式提交按钮。
2. 当前阶段提醒：结合上一条有效动作判断下一步倾向，例如刚输入关键词后应优先点击搜索/候选结果，刚输入评价文本后应判断是提交还是完成。

这种设计使模型不只看“当前截图”，还理解“任务已经走到哪一步”。它可以有效减少常见错误，例如搜索前误点推荐内容、输入后立即滚动、评价任务过早 `TYPE`、或结果尚未出现就 `COMPLETE`。

## 5. 动作解析与输出规范化

评测系统要求输出严格动作结构，但大模型可能出现 Markdown 包裹、大小写不一致、字段名变体、单引号 JSON、尾随逗号或夹带解释文本等情况。本方案设计了多层解析机制：

- 优先从完整输出中解析 JSON。
- 扫描所有花括号候选片段，选择最像动作对象的候选。
- 兼容 `action`、`Action`、`type`、`action_type` 等字段名。
- 兼容 `parameters` 和 `params`。
- 对智能引号、尾随逗号、布尔值/null 等 JSON-like 内容做归一化。
- 对坐标、文本、应用名等参数进行类型校验和清洗。

如果模型输出中没有可用 JSON，则进入兜底解析，尽量从自然语言式输出中恢复动作。所有动作最终都会被约束到评测允许的动作集合，避免非法动作导致直接失败。

## 6. 条件式自修复机制

本方案没有对每一步都进行二次模型调用，而是只在高风险场景触发修复，以平衡稳定性和成本。典型触发条件包括：

- 上一步刚 `TYPE`，当前动作却是明显可疑的滚动、重复输入或过早完成。
- 评价/评论任务中，输入后没有按任务意图选择提交或完成。
- 仍处于搜索前阶段时，模型试图滚动内容流。
- 内容互动任务首步误点右侧图标，而不是先打开目标内容。
- 表单填写任务还未进入输入态时，模型过早 `TYPE`。

修复提示会把原始动作和具体风险点反馈给模型，要求其重新判断当前屏幕下更合理的一步。修复结果还会经过质量判断，只有在明显更符合任务阶段时才替换原动作。该机制相当于为大模型决策增加了一层“风险门控”，避免无条件反复调用带来的不稳定。

## 7. 通用后处理规则

后处理模块是本方案提高泛化能力的重要组成部分。它不按照 APP 名称写固定路径，而是基于移动端界面的常见结构和任务阶段做动作校正，主要包括：

### 7.1 搜索与输入流程校正

对搜索类任务，系统会优先保证“进入搜索框 -> 输入关键词 -> 点击搜索/候选结果”的流程。如果模型在关键词未输入前误点推荐内容或直接滚动，会被纠正到搜索入口；如果输入后点击了明显不是搜索确认的位置，也会在部分场景中重定向到更可靠的确认区域。

### 7.2 表单与评价流程校正

评价、晒单、反馈类任务通常不是简单点击一次后立即输入文本，而需要先进入评价入口、选择星级/标签、激活正文框，再根据指令判断是否发布。本方案为这类任务建立了阶段化策略：

- 未进入表单时，优先寻找“评价”“写评价”“去评价”等显式入口。
- 文本框未激活时，避免过早 `TYPE`。
- 已完成多次表单点击且输入区出现时，倾向执行 `TYPE`。
- 输入文本后，根据“发布/提交/发送”等显式意图决定点击提交或直接完成。

### 7.3 内容互动任务校正

点赞、喜欢、评论区、收藏、分享等内容关系任务容易在列表页误点右侧栏图标。系统通过动作历史和任务关键词判断当前是否已经进入内容详情或全屏播放态：

- 如果仍在列表、搜索结果或推荐入口，首步倾向打开目标内容卡片。
- 如果已经进入内容页，再点击心形、拇指、评论或收藏等图标。
- 对竖屏内容流中常见的右侧图标栈，进行一定的纵向位置校准。

### 7.4 交易、路线与信息查询校正

对于购买、下单、支付、规格选择、路线查询、航班酒店筛选、价格查看等任务，系统更关注显式功能控件和完成条件：

- 交易任务优先底部操作栏、规格弹窗、确认按钮。
- 路线任务会根据指令抽取起终点并避免输入无意义文本。
- 价格任务只有在价格信息清楚可见或流程达到信息页后才允许完成。
- 播放选集类任务在后期重复选择同一集时，可判断为目标已达成。

## 8. 稳定性与安全控制

为提升评测环境中的运行稳定性，代码还加入了以下控制：

- 强制 UTF-8 运行环境，避免中文指令、日志和文本输入在不同机器上编码异常。
- 对 API 调用做短重试，只重试超时、限流、5xx 等临时错误。
- 对 401、403、鉴权失败、配置错误、token 超限等非重试错误立即抛出，不进行盲目调试。
- 对点击坐标做边界安全处理，避免贴边点击造成无效动作。
- 对应用名做别名归一化，提高 `OPEN` 动作在不同表述下的兼容性。

## 9. 泛化能力设计

本方案的泛化能力主要来自三点：

1. 视觉优先：所有决策都基于当前截图和网格坐标，不依赖隐藏状态或固定样例路径。
2. 任务族抽象：规则围绕“搜索、表单、内容互动、交易、路线、价格”等通用任务族，而不是绑定某个 APP 的固定页面。
3. 阶段化控制：利用历史动作判断任务进度，让同一个页面目标在不同阶段采取不同动作。

例如，同样是“评论”相关指令，在内容应用中可能意味着打开评论区，在电商应用中可能意味着填写商品评价。本方案不会直接套用某个固定坐标，而是结合指令关键词、历史动作和当前截图，让模型判断具体入口，再由后处理规则做通用约束。

## 10. 创新性总结

本方案的主要创新点如下：

- 双图视觉定位：同时提供原始截图和坐标网格截图，将多模态理解与精确坐标输出结合。
- 阶段感知提示：根据历史动作动态生成当前阶段提醒，使模型具备简单任务状态机能力。
- 条件式自修复：只在高风险动作上触发二次决策，兼顾稳定性、成本和输出一致性。
- 鲁棒 JSON 恢复：对非标准模型输出进行多候选解析和字段归一化，显著降低格式错误风险。
- 通用 UI 后处理：将移动端常见交互规律抽象成可复用规则，减少对单一 APP 或单一测试样例的依赖。
- 保守完成策略：只有在目标动作明显达成或目标信息可见时才 `COMPLETE`，降低提前结束导致的失败。

综合来看，该代理不是把任务写成固定脚本，而是构建了一个“视觉理解负责语义定位，规则系统负责流程约束和风险兜底”的混合智能体。该架构既保留了多模态大模型对未知界面的适应能力，又通过工程化控制提升了评测环境下的可靠性和可复现性。
